# Design

## Context

See proposal.md (Why) for the motivation. On `main`, `testConnection()` already calls `credentialStore.webDavConfig.first()`. The leak from the issue is therefore fixed in code, but only the "not configured" path is covered by a test, and the code has these gaps:
- `WebDavClient(config)` is created inline, so the success and failure paths cannot be unit-tested without a network.
- Nothing stops overlapping runs. The button is disabled while `isTesting` is true, but that only applies after recomposition, and other callers are not covered.
- The result strings are hard-coded, which breaks the project's string-resource rule, and the UI picks the colour with `result.startsWith("Connection successful")`.

## Goals / Non-Goals

**Goals:** cover every outcome with a regression test that proves no collector is left behind; add a re-entrancy guard; localize the results; stop the `collect` + `return@collect` pattern from coming back.

**Non-Goals:** reworking `startLoginFlow()`, whose `collect` is a legitimate multi-emission flow; the long-lived `init` collectors, which are meant to live as long as the ViewModel; changing the shared `WebDavClient` timeouts used by uploads.

## Decisions

1. **Keep `.first()`.** `first()` cancels the upstream flow after the first value. Alternatives were `take(1).collect` (same effect, less clear) and caching the latest config from the `init` collector (that couples the test to init ordering, and the value could be stale on the first tap).
2. **Re-entrancy guard with a `Job` reference.** Keep `private var testConnectionJob: Job?`. If `testConnectionJob?.isActive == true`, return immediately. The alternatives were checking `_uiState.value.isTesting` (UI state used as a lock, and it is set inside the launched coroutine, so two quick calls would race) and a `Mutex` (heavier, and it would queue calls instead of dropping them). The guard behaves like a lock, so it must always be released (see decisions 6–8): the check has an overall timeout and is cancellable, every failure becomes a result, and logout or a credential change cancels and nulls the job. It is also released when the ViewModel is cleared, since `viewModelScope` is then cancelled. (Code review: the original "always released by connect/read timeouts" claim was wrong — those are per-phase limits, a blocking `execute()` ignores coroutine cancellation, and logout left the job active.)
3. **Injectable connection check.** Add a constructor parameter `connectionTester: suspend (WebDavConfig) -> Result<Unit>` that defaults to `{ WebDavClient(it).testConnection() }`. It goes last among the defaulted parameters, so the `@JvmOverloads` constructor that takes only `(Application)` (guarded by `ViewModelFactoryRegressionTest`) stays available. A function type is enough here; a new interface would add nothing.
4. **Typed result, no raw text.** `sealed interface ConnectionTestResult` (in `ui/settings/ConnectionTestResult.kt`) has one case per user-actionable outcome: Success, NotConfigured, CertificateError, UnknownHost, ServerUnreachable, Timeout, AuthFailed (401/403), NotFound (404), HttpError(code), InvalidUrl, UnknownError. `Throwable.toConnectionTestResult()` does the mapping: `WebDavHttpException` by `code`; any `SSLException` or `GeneralSecurityException` in the cause chain (covers `SSLHandshakeException`, `SSLPeerUnverifiedException`, `CertPathValidatorException`, `CertificateException`) → CertificateError; `UnknownHostException`; `ConnectException`/`NoRouteToHostException`; `InterruptedIOException` (socket timeout and OkHttp call timeout); `IllegalArgumentException` (invalid URL from `Request.Builder.url`); else UnknownError. The screen resolves every case with `stringResource(R.string.connection_test_*)`; the colour comes from `is ConnectionTestResult.Success`. Only the exception class name is logged. The first version (`Failed(detail)` rendered as "Failed: <exception message>") was rejected in review: it showed raw text such as `java.security.cert.CertPathValidatorException …` and rendered "Failed: " for blank messages.
5. **Regression scan for the pattern.** Add a JVM unit test that walks `app/src/main/**/*.kt` (using the existing `krhnles.moduleDir` system property, like `NoLintSuppressionRegressionTest`) and fails on `return@collect`. Other places that take a single value from a flow (`AlbumsViewModel.getRepo`, `UploadWorker`) already use `first()`; the audit found no other offenders.
6. **Timeout and cancellation only for the connection test.** `WebDavClient.testConnection(timeoutMillis = CONNECTION_TEST_TIMEOUT_MILLIS /* 30 s */)` sets `call.timeout().timeout(...)` on that single call and awaits it with `enqueue` inside `suspendCancellableCoroutine`, `invokeOnCancellation { call.cancel() }`. `CancellationException` is rethrown, not wrapped in the `Result`. Alternatives: `callTimeout` on the shared client (rejected — it would also cap large uploads); `client.newBuilder().callTimeout()` (works, but allocates a client per test for no gain); keeping blocking `execute()` under `withContext(IO)` (ignores coroutine cancellation). Non-2xx statuses throw `WebDavHttpException(code, message)` (an `IOException`) with the same message as before, so callers relying on the text keep working and new code branches on `code` instead of parsing strings.
7. **Every failure becomes a result; cancelled jobs never publish.** `runConnectionTest()` wraps the config read and the check in `runCatching`, rethrows `CancellationException` and maps everything else, so a DataStore `IOException` or a throwing tester no longer escapes `viewModelScope`, and `isTesting` is always cleared. A `try/catch` of specific types was considered, but the tester is an arbitrary injected function; `runCatching` with an explicit cancellation rethrow keeps detekt's `TooGenericExceptionCaught` clean without a suppression. The job calls `ensureActive()` before writing its result. A `finally` that clears `isTesting` was rejected: after a cancel + new test it would clear the new test's spinner; instead the canceller resets `isTesting`/`testResult`.
8. **Cancel on session/config change.** `cancelConnectionTest()` cancels the job, nulls the reference and clears `isTesting`/`testResult`. `logout()` calls it synchronously, and the `init` `webDavConfig` collector calls it whenever URL, username or password differ from the previous emission (base-folder changes keep the result, since the check does not use it). Otherwise the guard would silently drop Test Connection after logout + re-login, and the old job could later write the old server's result into the new session.

## Risks / Trade-offs

- [The text scan could flag a legitimate `return@collect`, for example a deliberate per-emission skip] → The test message tells the developer to use `first()`, or `filter`/`continue`-style operators to skip values. If a skip is truly needed, `filter` expresses it without the early-return idiom.
- [The source scan is a line-based heuristic] → Known gaps: it only matches the literal `return@collect`; it misses custom labels (`collect lbl@{ … return@lbl }`), `collectLatest`/`collectIndexed` early returns, a label split across lines, and code inside string literals or after `/*` on the same line. It is a cheap tripwire, not a parser; code review remains the main defence.
- [A test started in the short window between saving new credentials and the config collector seeing them is cancelled] → The spinner stops without a result and the user can tap again; correctness (no stale result) wins over this rare case.
- [30 s overall limit may be short on very slow links] → Only the test uses it; uploads are unaffected, and the timeout message tells the user to retry.
- [Ignored taps give no feedback] → The button is already disabled and shows a spinner while a test runs, so the user sees that a test is in progress.

## Migration Plan

Nothing is persisted, so no migration is needed. To roll back, revert the commit.
