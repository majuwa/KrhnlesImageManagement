## Context

`PhotoGridScreen.kt` renders `PhotoItem` as `Box(Modifier.aspectRatio(1f).clickable(onClick))` containing an `AsyncImage` (`contentDescription = photo.displayName`), an optional cloud badge `Icon` (`cd_already_uploaded`) and a selection `Icon` (`cd_selected` / `cd_not_selected`). `clickable` merges descendants, so TalkBack reads the filename plus icon texts concatenated, without role, state or click label. `DateHeader` is a `Row` with `clickable` plus a `Checkbox(onCheckedChange = { onClick() })`, an extra separately focusable node. `Photo` has `dateTaken: LocalDate` (no time of day). `MediaRepository` reads `DATE_TAKEN` with `cursor.getLong`, so a null column becomes 0 and a 1970 date; `ShareIntentParser` uses today's date (always known). Remote grids (`AlbumDetailScreen` ~325, `BlurReviewScreen` ~301, `DuplicateReviewScreen` ~434) and `FullscreenViewerScreen` ~127 use `photo.displayName` as image description; `RemotePhoto` has no date.

Compose guidance: set `stateDescription`/`role`, give decorative children `contentDescription = null`, supply a click label.

## Goals / Non-Goals

**Goals:** one coherent TalkBack announcement per grid item and header; meaningful, localized, distinguishable descriptions instead of filenames everywhere in `ui/`; explicit state, role and action label whose action is the real one; regression tests on the semantics tree and the sources.

**Non-Goals:** changing the upload path of unknown-date photos (they still auto-upload to `1970/01-Jan`; known behaviour, pinned by `UploadBatchTest`, out of scope for an accessibility change; pre-1970 photos keep their real year folder), changing visuals (except the "Unknown date" header text), time-of-day in `Photo`, custom accessibility actions, reworking selection semantics of the remote grids.

## Decisions

1. **Local item description = "Photo %1$d of %2$d, taken on %3$s"** (`cd_photo_position_taken_on`; position = 1-based index within the day, total = photos of the day, date = locale `FormatStyle.LONG`). Position makes items of the same day distinguishable. Unknown date uses `cd_photo_position_date_unknown` ("Photo %1$d of %2$d, date unknown").
2. **One pattern for items and headers:** `Modifier.toggleable(value, role = Role.Checkbox, onValueChange = { onClick() })` followed by `semantics { contentDescription (item only); stateDescription = ...; onClick(label = ...) { onClick(); true } }`. Never a stub action: the labelled action invokes the real callback, so `performSemanticsAction(SemanticsActions.OnClick)` fires it exactly once (tested for items and headers). `selected` is dropped; the checked state comes from `toggleableState` (`ToggleableState.On/Off`). If modifier ordering lets `toggleable`'s unlabelled `OnClick` win over the labelled one, the semantics modifier is placed so the label wins; the tests (label present, callback fired exactly once) decide. No `semantics(mergeDescendants = true)`: `toggleable` already merges descendants, so it would be redundant and is not a guard.
3. **State text:** `stateDescription` = `cd_selected` / `cd_not_selected`; for uploaded photos `cd_photo_state_uploaded` = "%1$s, already uploaded". The uploaded flag stays in `stateDescription` (it is a state, read after the description and before role) rather than in the description, so it is announced once and does not change the stable description. Casing: spec, strings and tests all use lowercase "already uploaded" after the comma.
4. **Decorative children:** `AsyncImage`, uploaded badge and selection icon use `contentDescription = null`. Their information is carried by the merged parent. `cd_already_uploaded` is removed only after grepping all of `res/` and tests for references; `cd_selected` / `cd_not_selected` stay (reused).
5. **Click labels:** `action_select_photo` ("Select"), `action_deselect_photo` ("Deselect"), `action_select_day` ("Select all photos of this day"), `action_deselect_day` ("Deselect all photos of this day").
6. **Header:** `Row.toggleable(allSelected, role = Checkbox)`, `stateDescription` from `cd_selected`/`cd_not_selected`, label per 5, `heading()`. No new plural: the description is the merged texts (date `Text` + `photo_count` plural), so "1 photo" / "3 photos" is announced via existing resources. `Checkbox(checked = allSelected, onCheckedChange = null)` is decorative; the merged tree must contain exactly one checkbox-like node. Unknown date header text uses `date_unknown` ("Unknown date").
7. **Locale-aware date:** `val locale = LocalConfiguration.current.locales[0]`; `val formatter = remember(locale) { DateTimeFormatter.ofLocalizedDate(FormatStyle.LONG).withLocale(locale) }`; the strings are precomputed in `remember(photosByDate.keys, dateFormatter, unknownDateText)` (not on every selection change) and passed to header and items. Replaces the previous non-localized MEDIUM formatter. Tested with `@Config(qualifiers = "de")` and a locale change.
8. **Unknown date:** `Photo.UNKNOWN_DATE = LocalDate.EPOCH` sentinel; `MediaRepository` maps a null (`cursor.isNull`) or 0 `DATE_TAKEN` to it (without a time zone conversion). Negative values are real pre-1970 dates and keep their date (and upload folder); only a missing value is unknown. The sentinel is checked in one place (`LocalDate.isKnownDate()` in `model/Photo.kt`, also behind `Photo.hasKnownDate`). `ShareIntentParser` keeps today's date (known). UI shows "date unknown" / "Unknown date".
9. **Remote grids and viewer:** shared helper `photoPositionDescription(position, total)` ("Photo %1$d of %2$d", `cd_photo_position`) used for image descriptions in `AlbumDetailScreen` (`PhotoGridItem` becomes `internal`), `BlurReviewScreen`, `DuplicateReviewScreen` (position within the result list / duplicate group) and `FullscreenViewerScreen` (page index of the pager). Their existing selected/marked icon descriptions are unchanged.
10. **Source-scan guard:** a unit test walks all `*.kt` under `app/src/main/java/**/ui/` (module dir from the `krhnles.moduleDir` system property) and fails when the right-hand side of any `contentDescription` / `stateDescription` assignment (up to the top-level `,` / line end / closing bracket, strings opaque) mentions `displayName` or `href` (string templates, `stringResource(..., photo.displayName)`, `if` expressions), with matcher self-tests for these forms (positive/negative samples, like `NoLintSuppressionRegressionTest`).
11. **Testability:** `PhotoItem`, `DateHeader`, `PhotoGrid` and the album-detail `PhotoGridItem` are `internal` with only primitive/state parameters. Grid test data stays within one screen (few photos) or uses `performScrollToNode`. `AsyncImage` in Robolectric must be side-effect free: provide `LocalAsyncImagePreviewHandler` (or a fake `ImageLoader`) in tests so no network/ContentResolver load occurs; verify with Coil docs.
12. **Test assertions:** click-node count on the merged tree (`useUnmergedTree = false`), filename absence on the unmerged tree checking both `ContentDescription` and `Text`.

## Risks / Trade-offs

- Merging hides child icons from linear navigation: intended; state remains exposed. Tests assert it.
- `heading()` on the header combined with the checkbox role/state may make TalkBack announce "heading" plus "checkbox, not selected"; verify manually and drop `heading()` if too noisy.
- `stateDescription` replaces the default checkbox state text; if some TalkBack versions read state twice, adjust after the manual check (manual task).
- Sentinel date: a genuine photo dated local 1970-01-01 shows as unknown ("Unknown date"); accepted. A `DATE_TAKEN` of exactly 0 is indistinguishable from a missing one.
- Unknown-date photos still upload to `1970/01-Jan` (existing behaviour, deliberately unchanged and covered by a test); a follow-up could route them to an `unknown-date` folder.
- The decorative header `Checkbox(onCheckedChange = null)` would shrink from 48dp to ~24dp and change the header height; it keeps `Modifier.minimumInteractiveComponentSize()` so the layout is unchanged.
- Only `values` exists, so translations are not needed now.
