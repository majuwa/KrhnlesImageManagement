# Design

## Context

- `BlurViewModel.startScan()` filters `outcome.results` with `BlurDetector.DEFAULT_THRESHOLD` (3000). Scores come from `BlurAnalyzer` (max Laplacian variance inside ML Kit subject boxes, else whole image; 512 px analysis size). Documented bands for the 512 px pipeline: motion blur ~600-2000, sharp ~10000-30000+. `BlurState.Found` keeps only the blurry scores, so a different threshold cannot be applied afterwards without rescanning anyway.
- `BlurViewModel` is a plain `ViewModel` with `@JvmOverloads (blurScorerFactory, analysisDispatcher)` guarded by `PlainViewModelFactoryRegressionTest`; scans start only from `Idle`. Per-album inputs (`repositories`) are passed per call, never injected.
- `CredentialStore` already keeps non-credential preferences (`wifiOnly`, `autoDateFoldersEnabled`) in its DataStore, written with a plain `edit` (no `credentials_version` bump; that bump only accompanies changes to the encrypted prefs).

## Goals / Non-Goals

**Goals:** exactly the issue: 3-level setting in Settings, persisted, used by the next scan.
**Non-Goals:** numeric/custom thresholds, re-filtering, per-album values, scorer changes, showing the applied level in the review, new DataStore / backup changes.

## Decisions

1. **Levels and mapping.** `enum BlurSensitivity(threshold)`: `LOW=1500`, `MEDIUM=3000` (default; = `DEFAULT_THRESHOLD`, which stays the source for MEDIUM), `HIGH=6000`. A photo is blurry when `score < threshold` (strict). Higher sensitivity = higher threshold = more photos flagged. The numbers are unvalidated heuristics: scores differ between Nextcloud Memories previews and downsampled originals, and between content types; they are tuned only via this enum. Levels double (geometric) because variance scales roughly with the square of contrast.
2. **Persist the level name, in the existing store.** `CredentialRepository` gets `val blurSensitivity: Flow<BlurSensitivity>` and `suspend fun saveBlurSensitivity(BlurSensitivity)`, implemented in `CredentialStore` next to `wifiOnly` (string key `blur_sensitivity`, value = enum name, plain `edit`, same pattern, no `credentials_version` bump). Reading is type-safe: `prefs.asMap()[KEY] as? String` (a wrong-typed persisted value would otherwise throw `ClassCastException` from `prefs[KEY]`), then `BlurSensitivity.fromStored(String?)` -> MEDIUM for null / blank / unknown / wrong type. No new DataStore and no backup-rule change; consequently the setting is excluded from backup and device transfer with the rest of that file and is not restored on a new device (falls back to Medium). The credential store is not a security feature for this value; no security convention is changed.
3. **Control in Settings.** In the logged-in content next to the other toggles, a card like `AutoDateFoldersSetting`: title, hint ("High flags more photos"), visible level text and `Slider(0f..2f, steps = 1)`. The slider position is derived from the hoisted `level`; `onValueChange` rounds the value and calls `onLevelChange` whenever the rounded level differs from the current one (no `onValueChangeFinished`-only persistence, so keyboard/TalkBack steps persist as well; the unchanged-level guard avoids redundant writes). Material3's `Slider` is its own merging semantics node (it does not merge into a parent), so the slider itself is the single accessibility node: content description = title (reused string), `stateDescription` = level label, so TalkBack reads "Blur sensitivity, Medium" instead of a percentage; the visible title and level texts are hidden with `clearAndSetSemantics` so nothing is announced twice (the hint stays a separate text). Tests drive it via `SemanticsActions.SetProgress` only.
4. **Per-call sensitivity source, plain ViewModel.** `BlurViewModel` keeps its constructor. `findBlurryPhotos(photos, thumbnailUrls, repositories, sensitivity)` and `retryFindBlurryPhotos(...)` take `sensitivity: Flow<BlurSensitivity>`. The `ROUTE_BLUR` destination passes `CredentialStore(context).blurSensitivity` to `BlurReviewScreen`, which forwards it; a collected State value is never passed (it would be stale/recomposition dependent).
5. **Read once per scan, not retroactive.** In the scan job, after `Scanning` is published: `runCatching { withTimeoutOrNull(3_000) { sensitivity.first() } }` (rethrow `CancellationException`) `?: MEDIUM`. The level is used for the whole scan; later changes affect the next scan / Retry only. Scans still start only from `Idle` / Retry from `Error`; `BlurState` is untouched; no cached-score re-filter or rescan on change. Filtering uses `it < sensitivity.threshold`.
6. **Strings.** `blur_sensitivity_title`, `blur_sensitivity_hint`, `blur_sensitivity_low|medium|high` (reused for the visible text and the state description). No separate content-description string: the title is the label.

7. **Review follow-ups.** (a) `CredentialStore.snapshot` maps the DataStore to the inputs it depends on (server URL, base folder, `credentials_version`) and applies `distinctUntilChanged()` *before* decrypting, so blur / wifi / auto-date writes neither re-emit nor hit the Keystore (otherwise Settings' collector overwrote an unsaved base-folder edit). (b) `SettingsViewModel.setBlurSensitivity` counts pending saves: the blur collector ignores stored values while one is in flight (no flicker on a fast drag); on a non-cancellation failure with no save pending it restores `blurSensitivity.first()` (3 s timeout) and sets `blurSensitivitySaveFailed`, rendered via a string resource. (c) `clear()` (logout) resets the level to Medium, consistent with the other preferences (`prefs.clear()`); pinned by a test. (d) `readSensitivity` calls `currentCoroutineContext().ensureActive()` on failure, so only the scan's own cancellation propagates and a `CancellationException` from the source falls back to Medium. (e) `Context.credentialDataStore` is `internal` + `@VisibleForTesting(otherwise = PRIVATE)` (tests plant invalid values) and `NoCredentialDataStoreAccessRegressionTest` forbids its use outside `CredentialStore.kt`.

## Risks / Trade-offs

- Threshold values are heuristic and content-dependent (see decision 1); one enum to retune, Medium unchanged.
- The setting is not backed up (credentials DataStore is excluded wholesale); accepted for minimal scope.
- Users changing the setting expect old results to update; the issue explicitly says not retroactive.
