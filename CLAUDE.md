# AI Agent Instructions - Kröhnle's Image Management

You are an expert Android developer assisting in building "Kröhnle's Image Management", a privacy-first photo backup tool for WebDAV/Nextcloud.

## 🎯 Project Vision
To provide a manual, user-curated image backup flow where users select local device photos, tag them with an occasion, and seamlessly upload them to a WebDAV directory in the background.

## 🛠️ Tech Stack & Architecture
- **Language:** Kotlin (Strictly avoid Java).
- **UI Framework:** Jetpack Compose (No XML layouts).
- **Architecture:** MVVM (Model-View-ViewModel) with Clean Architecture principles.
- **Async & Background:** Kotlin Coroutines, Flow, and Android WorkManager for uploads.
- **Cloud Communication:** WebDAV protocol via OkHttp.

Only foreign `content://` URIs are uploaded (`isAllowedPhotoUri`, also in the worker) — exception: shared photos are uploaded from their app-private staged copy (`noBackupFilesDir/share_staging/<uuid>`, queue entry `staged` + `id = -1`, validated by `isValidStagedName` / `resolveStagedFile` in `worker/StagedFiles.kt`; the worker never reads the `uri` of a staged entry and never falls back to it). `ShareViewModel` (`ui/share/`) copies via `ShareStaging` (`upload/`, 100 MiB / file, 1 GiB / share, 2 GiB folder, free-space check, cancellable, partial / batch cleanup) before `finish()`; every provider call of a share (`getType` / `query` / open + copy) runs as `abandonableCall()` (`util/AbandonableCall.kt`: `CancellationSignal` passed to `query` / `openAssetFileDescriptor(uri, "r", signal)`, per-item timeout, detached so Cancel never joins a blocked provider; an abandoned result is released via `onAbandoned`), and shared types are allow-listed raster images only (`SharedImageType`, provider type → name extension via `MimeTypeMap` → concrete intent type); every queue-file deletion in the worker goes through `deleteQueueFile()` (deletes its staged files except those of the new retry file), and `ShareStaging.sweep()` (fail-closed, 7-day retry window judged by the retry file's own mtime, which `handleRetry` refreshes; retry files with unfinished / unknown unique work are kept) removes leftovers. Shared photos never carry a MediaStore id. Upload-folder failures use `FolderCreationError` strings, never album wording. `WebDavClient.uploadFile` streams a one-shot body (`Content-Length` from `contentLengthOf()` = `openAssetFileDescriptor(uri, "r").length`, `-1` = chunked) through the shared `executeCancellable` (`data/CancellableCall.kt`) on `uploadClient` (5 min read-timeout copy of `noRedirectClient`: never follows redirects, any 3xx fails — OkHttp would turn a 301/302/303 PUT into a GET; never a `callTimeout`; the length is computed inside the stream's `use`, failures → `-1`); 413 / 507 map to `UploadFailure` via `toUploadFailure()` (branch on the code) and their string resources in the result notification. Every `setForeground` goes through `setForegroundOrFalse()`: a refused foreground service returns `Result.retry()` and keeps the queue file (not after the last entry; from `interruptions + 1 >= MAX_UPLOAD_RUN_ATTEMPTS` it gives up (optional top-level `interruptions` in the queue file, absent = 0, clamped to `0..MAX_UPLOAD_RUN_ATTEMPTS` on read, written via `rewriteQueueFile()` before `Result.retry()`, reset in retry files; metered Wi-Fi-only wake-ups and constraint stops never count; hard backstop on `runAttemptCount`: give up at `MAX_UPLOAD_RUN_ATTEMPTS_BACKSTOP` = 10x the cap, or at `MAX_UPLOAD_RUN_ATTEMPTS` when the counter cannot be persisted) it gives up with the failure notification and a retry file for the rest). After each successful entry the queue file is rewritten atomically (`rewriteQueueFile()`, temp + rename) with `"uploaded": true` and the photo is marked at once; re-runs skip marked entries (absent marker = not uploaded, so old queue / retry files work) and history / notification / output count the whole batch. Upload work requests are built only by `uploadWorkRequest()` (explicit exponential back-off). Notification sentences are combined via `notification_text_with_reason` (`joinNotificationTexts()`), never concatenated in code. Auto date folders: one `UploadBatch.PerPhoto` (folder `YYYY/MM/DD` per photo, `Locale.ROOT` digits) per selection → one work; queue files are either single top-level `folderName` (occasion / old) or per-entry `folderName` + `label` with no top-level folder, detected from content by `parseUploadQueue()` (`worker/UploadQueue.kt`, strict `opt` + `is String` reads, mixed / non-string → malformed and deleted); folders are created via `WebDavClient.createDirectories()` (each level once) before any PUT.
5. **Error Handling:** WebDAV connections fail often due to self-signed certificates or bad URLs. Always provide clear, user-friendly error messages and retry mechanisms.
6. **One-shot Flow reads:** Read a single current value with `flow.first()` / `firstOrNull()`, never `collect { ...; return@collect }` — the early return does not cancel the upstream flow and leaks the collecting coroutine until its scope dies (issue #22 / #41, guarded by `NoCollectEarlyReturnRegressionTest`). ## 🔒 Security Conventions
- **Credential storage:** Both **username and password** are encrypted via the Android Keystore (AES-256-GCM) and stored in standard `SharedPreferences` (`krhnles_secure`). Only the server URL and base folder (non-sensitive) live in the unencrypted DataStore.
- **Encryption key:** Generated and managed by the Android Keystore (`AndroidKeyStore` provider) under the alias `krhnles_master_key`. The old `EncryptedSharedPreferences`/`MasterKey` approach was replaced because those APIs are deprecated.
- **Decryption failures:** `CredentialCipher.decrypt()` must not silently collapse failures into `null`; it maps crypto/Keystore/IO failures to a classified `DecryptResult`. `CredentialStore` logs failures once per distinct failure (field + exception type only, never secrets) and exposes `credentialState` (`Missing` / `Valid` / `Corrupted(KEY_INVALIDATED|UNREADABLE)`), which Settings surfaces to the user. Encryption recovers once (delete + regenerate key) from any failure classified `KEY_INVALIDATED`, including during key retrieval. Tests use `fakes/SoftwareKeyProvider` instead of the Android Keystore.
- **Credential flows & saves:** All credential-derived flows come from one snapshot flow (`flowOn(ioDispatcher)`) that maps the DataStore to the inputs it depends on (server URL, base folder, `credentials_version`) and applies `distinctUntilChanged()` *before* decrypting, so unrelated preference writes (blur sensitivity, Wi-Fi only, auto date) never re-emit or hit the Keystore; `Context.credentialDataStore` is `@VisibleForTesting` and must not be used outside `CredentialStore.kt` (guarded by `NoCredentialDataStoreAccessRegressionTest`). Any change to the secure prefs must be accompanied by a `credentials_version` bump in a DataStore edit, written *after* the prefs, or observers will not re-emit. `save()` encrypts everything before writing anything and throws `CredentialSaveException` on failure; callers must catch it and show a string-resource error.
- **Non-credential preferences in the credentials DataStore:** `wifiOnly`, `autoDateFoldersEnabled` and `blurSensitivity` (enum name under `blur_sensitivity`, read type-safely via `asMap()[KEY] as? String`, fallback Medium) are plain `edit`s without a `credentials_version` bump. They share the file's backup exclusion, so they are not restored on a new device.
- **Backup exclusion:** Upload queue and retry files (`upload_queue_*.json`, `retry_queue_*.json`, they contain per-photo capture days) are written to `context.noBackupFilesDir`, which is excluded from backup and device transfer automatically. The credentials DataStore (`datastore/credentials.preferences_pb`) is excluded from both cloud backup and device transfer via `backup_rules.xml` / `data_extraction_rules.xml`. The uploaded-photo markers DataStore (`datastore/uploaded_photos.preferences_pb`, device-specific MediaStore ids) is excluded in `backup_rules.xml` and both `data_extraction_rules.xml` sections, guarded by `BackupRulesTest` via `UPLOADED_PHOTOS_DATASTORE_NAME`. Its delegate uses `uploadedPhotosCorruptionHandler` (`ReplaceFileCorruptionHandler` -> empty set, pinned by `UploadedPhotosCorruptionHandlerRegressionTest`); `UploadedPhotosStore` has an internal `DataStore<Preferences>` constructor for tests, which never use the process delegate. The upload-history DataStore (`datastore/upload_history.preferences_pb`, user-written folder names) is excluded the same way (`UPLOAD_HISTORY_DATASTORE_NAME`, `BackupRulesTest`); its delegate uses `uploadHistoryCorruptionHandler` (pinned by `UploadHistoryCorruptionHandlerRegressionTest`), `UploadHistoryStore` has an internal `DataStore<Preferences>` constructor for tests, keeps at most 500 entries, makes colliding ids unique in `addEntry` and dedupes ids on read (newest wins); it is not cleared on logout.
- **XML parsing (XXE):** PROPFIND responses are stream-parsed by `PropfindEntryReader` (`data/WebDavXmlParser.kt`) with `android.util.Xml.newPullParser()` only. It sets `FEATURE_PROCESS_DOCDECL` false, reads the prolog with `nextToken()` up to the root `START_TAG` and rejects any `DOCDECL` (DOCTYPE, also benign) or `ENTITY_REF` with `MalformedMultistatusException`, requires the root `{DAV:}multistatus`, then uses `next()` only (KXml rejects a DOCTYPE after the root start tag, so no entity can be declared; undeclared references fail). The parser is created lazily inside `next()`'s try (KXml already reads in `setInput`): an `XmlPullParserException` whose `detail` / cause is a stream `IOException` (timeout, `Call.cancel()`, size cap) is rethrown unchanged, everything else (incl. an unsupported declared encoding) becomes `MalformedMultistatusException`. Never regex-strip DOCTYPE or use `DocumentBuilderFactory` / DOM. Parser tests run under `RobolectricTestRunner` so they use the production parser (no `kxml2` test dependency). Parser exception messages contain server content: log the exception type only, never `e` / `e.message`.
- **XML parse-cost bounds:** KXml grows its element / attribute / namespace arrays linearly, so hostile nesting or attribute counts cost quadratic time. `PropfindEntryReader` fails the whole response with `MalformedMultistatusException` on every start tag beyond `PropfindEntryLimits.maxDocumentDepth` (32), `maxAttributesPerElement` (64) or `maxNamespacesPerElement` (64), and wraps its input in `XmlTokenSizeLimitingInputStream` (`maxTokenBytes` = 64 KiB between two markup starts, i.e. per tag or coalesced text node incl. CDATA / comments) so a huge tag or text node fails before KXml buffers it. Never remove these checks; regression tests with time bounds are in `PropfindEntryReaderTest`.
- **Auth flow origin validation:** `NextcloudAuthRepository.validateSameOrigin()` ensures the `pollEndpoint` and `loginUrl` returned by the server share the same origin as the configured server URL, preventing token theft and phishing via a compromised server response.
- **Auth polling timeout:** `NextcloudAuthRepository.loginFlow()` enforces a maximum polling duration and fails with a user-facing timeout message instead of polling forever.
- **HTTP warning:** `SettingsUiState.httpWarning` is set to `true` when the user explicitly types an `http://` URL; the UI should surface a warning about plaintext credentials.
- **Minification:** Release builds have `isMinifyEnabled = true`.
- **Album config changes:** `AlbumDetailViewModel` observes `webDavConfig`; on logout or a server / account change it cancels a running load and deletion, drops its repository and clears the album (`AlbumsError.NotConfigured` / `ConfigurationChanged`), so an open album never lists or deletes on the old server with old credentials.
- **File id validation:** `parsePropfindXml()` keeps an `oc:fileid` only if it matches `[A-Za-z0-9]+` (it is placed in the Memories preview URL); `checkMemories()` logs the exception type only.
- **Thumbnail download hardening:** `AlbumsRepository.downloadBitmapForHash(url)` only requests URLs below the configured base folder or the Nextcloud Memories preview of a file id (`<nextcloudBase>/index.php/apps/memories/api/image/preview/<id>`) on the configured origin; anything else fails with `UnsafeHrefException` without a request. The body is read through `LimitedInputStream` (`MAX_THUMBNAIL_BYTES` = 32 MiB, also checked against `Content-Length`; larger → `ThumbnailTooLargeException`) via `executeCancellable`, never `body.bytes()`.
- **WebDAV path hardening:** `WebDavClient` validates path segments (`.` / `..` forbidden) and uses `HttpUrl` path-segment encoding to prevent traversal and malformed URL injection.
- **Bounded PROPFIND listings:** Never `body.string()` / DOM-parse a PROPFIND (issues #27 / #46, guarded by `NoDomPropfindRegressionTest`). Read the decompressed `byteStream()` through `LimitedInputStream` (`MAX_PROPFIND_RESPONSE_BYTES` = 32 MiB) into `PropfindEntryReader` (per-entry limits in `PropfindEntryLimits`; oversized entries are skipped, only counted). `listPhotos(albumHref, onProgress)` returns `PhotoListing(photos, isTruncated)` (cap `MAX_PHOTOS_PER_ALBUM` = 20,000, duplicate hrefs dropped, publish once at the end; truncation is shown on the album and both reviews); `listAlbums()` fails with `AlbumsError.ListingTooLarge` above the byte cap, never truncates. Without a complete entry besides the album collection, the byte cap fails as `MalformedMultistatusException`; a truncated listing with zero photos shows `album_truncated_empty_notice`, not the empty-album message. Blocking OkHttp reads are made cancellable with `executeCancellable(call)` (sibling `launch(UNDISPATCHED) { try { awaitCancellation() } finally { call.cancel() } }`), not `invokeOnCompletion`; it calls `ensureActive()` for *every* non-cancellation exception (a parser may wrap the cancelled read). `AlbumDetailViewModel.startLoad` calls `ensureActive()` and checks its load generation before publishing a result *or an error*, and resolves thumbnail URLs on its injectable `backgroundDispatcher` (not Main).
- **Server href validation:** Never build a URL as `"$origin$href"` from a server-supplied href (PROPFIND `d:href`). Use `resolveWebDavHref(root, href)` (`data/WebDavHref.kt`): it rejects `.` / `..` (also percent-encoded), encoded `/` or `\`, backslash, query and fragment on the *raw* href (before `HttpUrl.resolve()` normalizes dots away), then requires the same scheme/host/port and a path strictly below `root` (`AlbumsRepository`: the configured base folder; listed photos: their album). Skip unsafe entries in listings; fail requests for them with `UnsafeHrefException` without sending anything; never log the href or credentials.
- **Auth interceptor origin restriction:** OkHttp interceptors that add `Authorization` (`AlbumsRepository`, `WebDavClient`, the Coil image loader in `KrhnlesApplication`) must only do so when `request.url.hasSameOriginAs(configured URL)`; credentials are never sent to another host or port.

## After Every Code Change

After adding a feature or making any code change:

1. **Run all tests** — `./gradlew test` must pass before considering the change done.
2. **Update `README.md`** — if the change affects user-facing behaviour, features, gestures, or visual design.
3. **Update `CLAUDE.md`** — if the change affects architecture, key conventions, package structure, tech stack, or testing patterns.
4. **Run Spotless** -`./gradlew spotlessCheck` spotless muss pass before considering the change done
5. **Run Detekt** - `./gradlew detekt` — no new detekt issues or ask the user whether they are ok
6. **Run Android Lint** — `./gradlew lintDebug` must pass with zero issues (no baseline — all issues must be fixed)
7. **Generate coverage** — `./gradlew jacocoTestReport` produces an HTML report at `app/build/reports/jacoco/jacocoTestReport/html/` (class dirs: `intermediates/built_in_kotlinc/debug/...`; unit tests run with `isIncludeNoLocationClasses = true` so Robolectric-loaded classes are counted)

## 🌐 String Resources
- All user-facing strings are in `app/src/main/res/values/strings.xml` — never hardcode strings in Kotlin/Compose.
- Use `pluralStringResource(R.plurals.xxx, count, count)` for count-dependent text (e.g. "1 photo" / "3 photos").
- In non-Composable contexts (workers, callbacks), use `resources.getQuantityString(R.plurals.xxx, count, count)`.
- In Compose callbacks, use `LocalResources.current` (not `LocalContext.current.resources`) to ensure Configuration-change awareness.

## Coding Guidelines
* do not suppress issues, unless asked to
* if suppress is best decision ask whether it should be done or an alternative should be found
* if a lock or something similar is required, use if possible a timeout so that it will be release
* for every bug request think what are meaningful test can be so that the bug won't happen in the future
* do not disable test unless you asked for permission
