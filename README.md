# Kröhnle's Image Management (KröhnSync)

A lightweight, privacy-focused Android application designed to selectively back up your local photos directly to your personal Nextcloud or WebDAV server. Instead of fully automated background dumps, this app puts you in control of what gets uploaded and how it's organized.

## 🚀 Features

- **First-Run Introduction:** On the first launch of a fresh install a two-page introduction explains what the app does and offers "Connect now", which opens Settings (Back from Settings returns to the photo grid). Skip is available on both pages; it is shown only once and never to users who already set up a server. Pressing Back on the first page closes the app and shows the introduction again next time. The completion flag is not part of backups, so a restored device without credentials shows the introduction again.
- **Local Image Grid:** Browse photos and videos stored on your device in a clean, high-performance grid, grouped by capture day (newest first). Video tiles show a frame of the video, a play icon and the duration (`1:05`, `1:02:03`); videos without a capture date are grouped under "Unknown date" like photos.
- **Videos:** Videos are selected and uploaded exactly like photos (occasion or auto date folders, background upload, Retry Failed, uploaded marker). They are streamed, never loaded into memory, and their size is sent when the device reports it. If the server rejects a file as too large (HTTP 413) or has no storage left (HTTP 507), the result notification says so. If an upload is interrupted (for example because Android's background time budget for uploads is used up), it is retried later and continues with the items that were not uploaded yet. After five interrupted attempts the upload stops with a notification offering "Retry Failed" for the remaining items. Videos in your server albums are shown in the Albums tab (see Cloud Album Browser), but the duplicate / blur reviews only handle photos. Sharing videos into the app is not supported.
- **Large Videos on Nextcloud:** On Nextcloud (server address `…/remote.php/dav/files/<user>/`, as set up by the Nextcloud login) every file of at least 50 MB is uploaded in parts of 10 MB (Nextcloud chunked upload), so it also works when the server or its proxy limits the size of one request (for example 512 MB). The progress notification then also shows how far that file is ("1 / 3 · 50 %"). An interrupted upload (background time budget used up, app closed, phone restarted, network drop) continues after the last part the server confirmed instead of starting the file again; before continuing, the app re-reads the part already sent on the device and starts the file over if it changed. Short network or server hiccups are retried up to 3 times during the same upload. If the server cannot take chunked uploads, the app falls back to one request per file. Cancelled, failed or abandoned parts are removed from the server (otherwise Nextcloud removes them after 24 hours); "Retry Failed" always starts such a file from the beginning. Verification works as for other uploads. Plain WebDAV servers and other Nextcloud addresses (for example `/remote.php/webdav/`) keep uploading each file in one request.
- **TalkBack Support:** Every photo in the grid is announced as one element ("Photo 2 of 5, taken on May 1, 2026", selected / not selected, already uploaded) with a "Select" / "Deselect" action, videos as "Video 1 of 2, 1 minute 5 seconds, taken on May 1, 2026" (no duration when it is unknown), and each day header as one heading with its item count ("3 items", photos and videos) and a "Select all items of this day" action. File names are never read aloud; photos without a capture date are announced as "date unknown" and grouped under "Unknown date". Album thumbnails and the fullscreen viewer announce "Photo N of M" and "Video N of M" (the play icon and the placeholder are not read separately); the viewer's video controls (play / pause, seek bar with "30 seconds of 2 minutes") have spoken labels.
- **Smart Selection:** Select images individually or batch-select them grouped by date.
- **Custom or Automatic Foldering:** Either give each upload a custom occasion name (e.g., "Summer Vacation 2026") or enable automatic `YYYY/MM/DD` day folders for quick archive uploads.
- **Background Uploads:** Hit upload and move on with your day. Uploads are handled in the background.
- **Cancel a Running Upload:** The upload progress notification has a **Cancel** action, and the progress banner on the Photos tab a **Cancel upload** button (no confirmation, because cancelling is resumable). The photo or video being sent stops at once and nothing more is sent. Everything uploaded before the cancel stays uploaded (cloud badge, verified uploads); the rest is kept, and the result notification "Upload cancelled" says how many were uploaded and how many were not (not "failed") and offers "Retry Failed (N)" to upload only those, each into its original folder. The item being sent when you cancelled starts again from the beginning, and a partly transferred file may remain on a plain WebDAV server until the retry replaces it. Photos shared into the app keep their private copies for the retry (7 days from the cancel). Only a running upload can be cancelled. Android stopping an upload on its own (no Wi-Fi with Wi-Fi only, system time limits) is not a cancel: the upload continues later by itself.
- **Upload History:** Review past upload batches (folder, timestamp, succeeded/failed counts; a cancelled upload shows as "Cancelled · X uploaded · Y not uploaded") and clear entries individually or all at once. The history stays on the device when you log out, so on a shared or handed-over device folder names remain visible until you use "Clear all".
- **Verified Uploads:** Every photo and video uploaded from the device is checked against the server. On Nextcloud the server computes a SHA-256 of the stored file while it is written (`X-Hash`) and the app compares it with the one it computed while sending, without an extra request. On other WebDAV servers the check needs the setting **Verify by downloading again** (Settings, off by default): the file is downloaded once more and compared, which uses extra data (also on Nextcloud, if the server does not answer with a hash). Without a hash and without that setting an upload counts as before but is not verified. A file whose check shows different content, or that could not be checked, counts as failed (the notification says "A file could not be verified on the server" and offers Retry Failed). Photos shared into the app are never verified.
- **Remove Uploaded Photos from Device:** The three-dot menu of the Photos screen offers "Remove uploaded photos from device". It checks every verified upload: it was uploaded to the current server, it is unchanged on the device (size and modification time) and the server still has a file of that size. You then see "Move N photos and videos to trash?" followed by Android's own confirmation. Photos and videos go to the system trash, where you can restore them for about 30 days; nothing is deleted on the server or permanently. Removal only ever happens through this action, per photo, never automatically after an upload, and the app asks for no special storage permission. The result says how many items are confirmed in the trash. Photos uploaded before this feature, shared photos, unverified uploads and photos uploaded without the media location permission are never removed; neither is a photo whose server file was later overwritten by another upload with the same name, nor anything already in the trash. If the server fails or does not answer five times in a row, the check stops with "Server not reachable" and keeps every photo; if the confirmation stays open for more than ten minutes, the whole check (including the server) runs again before anything is moved. The record of verified uploads stays on the device (not in backups) and is cleared when you disconnect or connect to another server or account.
- **Duplicate-Upload Prevention:** Already-uploaded photos are marked with a cloud badge in the local grid. Use the filter toggle (funnel icon) to show only new (not yet uploaded) photos. The tracking is reset when you disconnect from the server. You can still select and re-upload marked photos. The markers are device-specific and are not restored from a backup or on a new device.
- **WebDAV & Nextcloud Native:** Direct integration with your self-hosted storage.
- **Secure Login:** Nextcloud Login Flow v2 (browser-based) or manual WebDAV configuration. Credentials are encrypted at rest; if they can no longer be decrypted (e.g. after device security settings change), Settings explains why and asks you to log in again. If saving credentials fails, an error is shown and you can retry.
- **Cloud Album Browser:** Browse albums (folders) stored on your WebDAV/Nextcloud server. Albums show photos and videos (MP4, M4V, MOV, 3GP, 3G2, WebM and MKV; other video types are not listed). A video tile shows a play icon on a poster picture; the poster comes from your server's own preview (Nextcloud Memories or Nextcloud's preview, which needs the video preview generator of your Nextcloud, for example with ffmpeg). Without a preview, or on a plain WebDAV server, the tile shows a movie placeholder: the app never downloads a video just to show a thumbnail.
- **Save Album Photos to the Device:** In the Albums tab, tap "Save to device" in the fullscreen viewer (photo pages only) or select photos with a long press and use the download icon in the top bar. The photos are downloaded in the background (a progress notification with Cancel; it keeps running when you close the app, continues after interruptions and lost connections, and one batch runs after the other) and appear in your gallery under `Pictures/KroehnSync/<album name>/`. Only images are saved (JPEG, PNG, GIF, WebP, HEIC, HEIF, AVIF, BMP, DNG; videos and other types are reported as unsupported), up to 200 MB each; the original file is saved, never a preview. Nothing is ever overwritten (a taken name gets " (1)"), nothing incomplete is ever visible, and no storage permission is needed. Saved photos are new photos on your device: they are not marked as uploaded and "Remove uploaded photos from device" never offers them. Cancelling also cancels the batches queued after it. A notification reports how many photos were saved and why others were not.
- **Play Videos from the Album:** Tap a video in an album to open it in the fullscreen viewer and tap the play button. The video is streamed from your server only (never stored on the device, nothing is preloaded, and nothing is sent to a third party); you can pause, seek and swipe to the next item (which stops the video). Playback also stops when you log out or the server changes, pauses when the app goes to the background and keeps playing when you rotate the screen. Credentials are only sent to your configured server, redirects are never followed and a trusted self-signed certificate is honoured like everywhere else. The device decodes the video: formats it cannot play, for example some 10-bit HEVC or Dolby Vision recordings, show "This video format is not supported on this device." Streaming uses mobile data when you are not on Wi-Fi (the Wi-Fi-only setting only applies to uploads).
- **Large Albums:** Opening an album shows how many items have been found so far while the listing loads, using little memory even for albums with tens of thousands of photos. Very large albums (more than 20,000 photos and videos together, or a 32 MiB folder listing) show only their first items together with a notice (or, if none of the part that could be loaded contains photos or videos, an explanation instead of "No photos or videos in this album."); the duplicate and blur review then warn that their results may be incomplete. A folder list that is too large to load shows an explanation instead of a partial list.
- **Cloud Duplicate Detector:** Scan an album for near-duplicate images and bulk-delete the extras (videos in the album are ignored; the review buttons only appear when the album has photos).
- **Delete Photos from Album:** Long-press any photo or video in an album to enter selection mode. Select multiple items, then tap the delete icon in the top bar. A confirmation dialog is shown before any server deletion. Photos that could not be deleted stay in the album, and a snackbar on the album screen reports how many deletions failed — also after deleting from the duplicate or blur review, which return to the album once the deletion has finished. Back (and the top-bar back / cancel-selection buttons) is disabled while any deletion runs, so it always finishes. Photos that were already deleted elsewhere (server answers "not found") are treated as deleted. Logging out or switching servers while a duplicate or blur review is open stops its scan and shows an error instead of its results. Rotating the screen during a duplicate or blur scan, on its results or while deleting keeps the scan, your selection and the deletion.
- **Search and Sort Albums:** The Albums tab has a search field that filters the album list by name while you type, ignoring case and accents ("cafe" finds "Café", "strasse" finds "Straße"); a blank search shows all albums and a search without a match says so. The search text is kept when you rotate the screen, switch tabs, refresh, rename or delete. The sort button in the top bar offers Name A–Z (default), Name Z–A, Last modified (newest first) and Last modified (oldest first); albums for which the server reports no modification date are always listed last. The modification date is the one your server reports for the folder (Nextcloud also updates it when files inside change; other servers may only update it when direct entries change). Your sort choice is remembered across restarts, reset to Name A–Z on logout and not restored from backups or on a new device. Changing the search or the sort shows the list from its first album. Only the first 255 characters of an album name are used for search and name order. A renamed album moves to the position the current sort gives it. Note: with auto date folders the albums list shows the year folders (e.g. `2026`) as top-level albums; browsing into the month / day sub-folders is not yet supported.
- **Manage Remote Albums:** Long-press an album in the Albums tab to rename it or delete it from the server, with confirmation and inline validation. Rename never overwrites: the new name is trimmed, must not be blank, unchanged, `.` / `..` or contain `/` or `\`, and is at most 255 UTF-8 bytes; an already existing name is reported (HTTP 412). A rename that gets no answer within 30 s is cancelled and the list is reloaded because the server may still have completed it (the same happens if the server answers with an unexpected 2xx such as 207, with a note that the rename may be incomplete). Known limitation: uploads still queued or waiting for a retry keep the old folder name and may re-create the old album after a rename.

## 🛠️ Tech Stack
- **Language:** Kotlin
- **UI:** Jetpack Compose
- **Image Loading:** Coil
- **Background Processing:** Android WorkManager
- **Networking:** OkHttp (WebDAV via PROPFIND/MKCOL/PUT)
- **Security:** Android Keystore (AES-256-GCM) encrypted credential storage
- **Server-response hardening:** Album and photo paths returned by the server are only used if they stay on the configured server and inside the configured base folder; credentials are only ever sent to the configured server

## ⚙️ Setup & Installation

1. Clone the repository
2. Open in Android Studio (Ladybug or newer)
3. Sync Gradle and build
4. Run on a device with Android 15+ (API 35+)

### Permissions
- **READ_MEDIA_IMAGES**, **READ_MEDIA_VIDEO** and **READ_MEDIA_VISUAL_USER_SELECTED** — requested together to browse device photos and videos. Any of them is enough to use the grid. With partial access ("Select photos and videos") a banner offers "Select more photos and videos"; the app never asks again on its own. Users upgrading from a photos-only version are asked for video access once; without it photos keep working and a banner offers to allow videos (or opens the app settings once Android no longer shows the dialog after a second denial; a dismissed dialog can simply be shown again). Granting more access (videos, or full instead of selected access) updates the grid immediately.
  - Publishing note: `READ_MEDIA_VIDEO` requires the Google Play Console "Photo and Video Permissions" declaration.
- **ACCESS_MEDIA_LOCATION** — requested together with the media permissions (it is not needed to use the grid). With it the app uploads the original files, so backups keep the photos' location (GPS) data; without it Android hands out copies with the location removed. Such uploads still work but are never verified, so those photos are never offered by "Remove uploaded photos from device" (removing them would lose the location). Users who already granted media access are asked once; partial-access users are never asked automatically, and a denial shows no banner.
- **INTERNET** — required for WebDAV uploads
- **POST_NOTIFICATIONS** — for upload progress notifications

### Configuration (Nextcloud)
1. Open the app and tap the Settings icon in the top bar
2. Enter your Nextcloud server URL (e.g., `https://nextcloud.example.com`)
3. Tap "Connect via Browser" — you'll be redirected to log in securely
4. After approving in the browser, the app receives an app-specific token automatically

### Configuration (Manual WebDAV)
1. In Settings, expand "Manual WebDAV config"
2. Enter the full WebDAV URL, username, and password/app token
3. Tap "Save & Connect"

### Test Connection
If the album list, an album or a duplicate / blur scan cannot be loaded, the same plain-language explanations are shown (not logged in, invalid server address, certificate, server not found / unreachable, timeout, access denied, not found, HTTP error); retry with the Retry button (album, scans) or the reload icon (album list). Logging out or switching servers while an album is open closes that album's photos instead of continuing to use the old server.

In Settings, "Test Connection" checks the stored server and credentials (it gives up after 30 seconds). Failures are explained in plain language: an untrusted (e.g. self-signed or expired) certificate, a server name that cannot be found, an unreachable server, a timeout, rejected credentials (HTTP 401/403), a missing WebDAV folder (HTTP 404), or another HTTP error code. Tap the button again to retry. Logging out or changing the server or credentials clears the previous result.

#### Servers with a self-signed certificate
If the test reports an untrusted certificate (for example a self-signed one), Settings shows the certificate for review: SHA-256 fingerprint, subject, issuer, validity and the server it would be trusted for. Compare the fingerprint with the one on your server (for example `openssl x509 -noout -fingerprint -sha256 -in cert.pem`), then tap "Trust this certificate" and confirm the dialog. The test runs again and, from then on, album lists, thumbnails and uploads accept exactly that certificate for exactly that server (host and port) while it is valid; every other connection keeps using the system trust store. The review also shows the certificate's public key; expired or not-yet-valid certificates and weak keys (RSA below 2048 or EC below 256 bits) can be reviewed but not trusted. "Stop trusting" in Settings removes it again, and logging out or saving credentials for a different server removes it too (it is never restored from a backup or on a new device).

If the server later presents a different untrusted certificate, the app reports "certificate changed" (in Settings, on the album screens and in the upload notification) and shows the new and the previously trusted fingerprint (also in the confirmation dialog). If you did not replace the certificate yourself, someone may be intercepting the connection; trust the new one only if you are sure. The Nextcloud login does not support self-signed servers: enter the server address, username and an app password manually, save, and then run "Test Connection".

### Upload Options
- **Base upload folder:** Choose the remote root folder that all uploads go into.
- **Auto date folders:** Optional toggle in Settings that skips the occasion dialog and uploads each photo into the folder of its capture day, `YYYY/MM/DD` such as `Photos/2026/05/14/` (digits only, independent of the device language). A selection that spans several days is still one background upload with one progress notification, one result notification and one upload-history entry (for example `2026/04/30 – 2026/05/01`). Existing `YYYY/MM-Month` folders from earlier versions are left untouched.
- **Upload on Wi-Fi only:** Switch in Settings (off by default; the whole row is one switch for screen readers). When on, uploads, including "Retry Failed", only run on an unmetered network: a metered Wi-Fi hotspot waits, an unmetered mobile plan uploads. Uploads queued while it was on keep waiting for an unmetered network even after you switch it off (use Retry to send them sooner). The retry back-off may grow to 5 hours after repeated waits on a metered network; these waits do not count towards giving up. The setting is reset when you log out and not restored on a new device.
- **Verify by downloading again:** Switch in Settings (off by default; the whole row is one switch). Downloads every uploaded photo and video once more to check it arrived intact, so it roughly doubles the data of an upload; use it for servers that cannot check uploads themselves (not needed on Nextcloud with hash support). It also applies to Wi-Fi-only: the download is part of the upload and waits for an unmetered network. Not restored from a backup or on a new device.
- **Blur sensitivity:** Slider in Settings (Low / Medium / High, default Medium) that decides how aggressively the blur review flags photos: High flags more photos, Low only clearly blurry ones. A changed level applies to the next blur scan only; results already shown or being computed are not updated. The setting is stored with the other preferences and, like them, is not restored on a new device and is reset to Medium when you log out. The thresholds are heuristics and may need tuning for your camera.

### Usage
1. Grant photo and video access when prompted
2. Browse your photos grouped by date
3. Tap individual photos or date headers to select
4. Tap the upload FAB (cloud icon) when photos are selected
5. Either enter an occasion/folder name (up to 5 suggestions from your recent occasions and the existing albums on the server appear below the field; tap one to fill it in; the server albums are best-effort and may be missing, and the history of a previously used server may appear; folders named like a year, e.g. `2026`, are not suggested; opening the dialog contacts your server to list the folders, also on mobile data), or confirm the auto-date folder preview if that mode is enabled
6. Upload proceeds in the background with notification progress
7. Open the history icon in the Photos top bar to review previous upload results
8. If some photos fail (for example a network error or a photo that can no longer be read), the result notification offers "Retry Failed (N)": it re-uploads only those photos into the same folder, respects the Wi-Fi-only setting and dismisses that notification. Photos shared from other apps are retried from the app's private copy for 7 days (counted from the last failure or Retry tap); after that the copy and the retry are discarded. Each retry appears as its own entry in the history. If the remote folder cannot be created, the notification explains why in plain language. Occasion names cannot be `.` or `..` or contain `/` or `\`. With Wi-Fi-only on, an upload that starts on mobile data waits and retries later. Only photos from other apps' content providers can be shared in; `file://` shares are ignored.

### Sharing photos from other apps
Share one or more images (up to 100 at a time) from any app's share sheet to Kröhnle's Image Management, enter an occasion name (or tap one of the suggested recent occasions / existing albums; the share target contacts your server for the album list, also on mobile data) and tap Upload. The photos always go into that occasion folder, also when auto date folders are on. Before you are returned to the sharing app, the photos are copied into app-private storage (excluded from backups) with a "Preparing x of n" progress and a Cancel button, so the upload still works later, on Wi-Fi only or after the app was closed. Cancel or Back stops the copy and nothing is uploaded. Supported formats are JPEG, PNG, GIF, WebP, HEIC/HEIF, AVIF, BMP and DNG (no SVG); the uploaded file name always ends with the matching extension. Other items, items that cannot be read (also an app that does not answer in time) or are larger than 100 MB are skipped and reported; photos that no longer fit into the 1 GB limit of one share are reported separately, and if none of the photos could be read nothing is uploaded and the app says so. A share needs some free storage. A photo with the same name as a file already in the occasion folder replaces it. If no server is set up yet, the app asks you to set it up first (Open app). The copies are deleted when the upload is finished, except those of failed photos, which are kept for "Retry Failed" for up to 7 days.
